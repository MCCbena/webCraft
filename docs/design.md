# WebCraft — Web言語製Minecraftクローン 設計書

## 1. 要件(ユーザー指定)
- Web言語(TypeScript)でMinecraft風ゲームを作成
- Java Edition 1.13 仕様のレッドストーン回路(ダスト伝播・リピータ・コンペア・ピストン・オブザーバ等)
- 16チャンク地形生成 → **16×16チャンクの世界(256×256ブロック、高さ256)** をシード付き決定論的に生成
- サバイバルモード(HP・空腹・ダメージ・インベントリ・ブロック採掘/設置)
- クリエイティブモード(飛行・即破壊・無限アイテム)
- gitでバージョン管理
- その他は実装者判断で補完(UI・テクスチャ・サウンド等)

## 2. 技術スタック
- TypeScript + Vite + Three.js(レンダリング)
- Vitest(ユニットテスト、ブラウザ不要の純ロジックテスト)
- 外部アセット不使用:テクスチャは Canvas で 16×16 タイルのテクスチャアトラスを生成
- Node 24 / npm / git 使用

## 4. ブロック・アイテム定義(core が Phase 1 で全定義)
- 地形系: air, stone, grass, dirt, sand, gravel, log(oak), leaves, planks, cobblestone, glass, water, bedrock, clay, snow(簡易)
- 鉱石系: coal_ore, iron_ore, redstone_ore
- レッドストーン系(1.13): redstone_dust, redstone_torch, redstone_block, redstone_lamp(+lit), repeater(向き+1~4tick), comparator(向き+compare/subtract), piston(向き), sticky_piston(向き), observer(向き), lever(on/off), stone_button, wood_button, stone_pressure_plate, wood_pressure_plate, tripwire_hook(簡易可), dispenser, dropper(中身簡易可)
- 機材系: torch, door(oak, 半ブロック)
- プロパティ: solid, opaque, hardness(破壊時間), drop(ドロップアイテム), meta(向き0-3 / オンオフ / 強度等)
- アイテム: 各ブロック + wheat, bread(空腹+5), apple(空腹+4), stone_pickaxe(等), 最低限のツール

## 5. ワールド・チャンク
- チャンク: 16(X)×256(Y)×16(Z)。`Uint8Array` 2枚(id / meta)。index = (y*16+z)*16+x
- 世界: 16×16チャンク(256×256ブロック、座標 -128..127、中心スポーン (0, 最高地点, 0))
- 生成: 決定論的シード(デフォルト 1337、URL ?seed= で変更)。Perlin/Simplex ノイズ(自作実装可)
- メッシュ: 表示距離 ±3 チャンク(7×7=49チャンク)のみメッシュ化、プレイヤー移動で再計算。バックグラウンド生成はチャンク単位の lazy
- 水: 半透明マテリアル、フェーズ分離メッシュ
- 保存: localStorage に世界シード・プレイヤー状態(簡易、任意)

## 6. 地形生成(16×16チャンク、1.13風)
- 高さ: 多倍オクターブノイズ。ベース y≈64、山脈帯(山:最高≈200)
- バイオーム: 平野(草)、森(樹木密度高)、砂漠(砂+枯れ草)、山岳(岩+雪)、海洋(水深1-8、砂底)
- 樹木: オーク(幹4-6、葉のブロック)、森で高密度
- 鉱石: 石の内部に鉄・石炭(浅い)/レドストーン(深い、y<16)をクラスタ配置
- ベドロック: y=0 層(y<8 に混在)
- 決定論: 同じシードで同じ世界(テスト対象)

## 7. プレイヤー
- 操作: 鼠标+キーボード(ポインタロック)、WASD移動、Spaceジャンプ、左クリック破壊(長押し)、右クリック設置、1-9/ホイール選択、Eインベントリ、Fモード切替、F3デバッグ
- 物理: AABB(幅0.6×身長1.8)、重力、摩擦、水内減速(簡易)、落下ダメージ(生存)
- サバイバル: HP20(心10)、空腹20、空腹0でHP減少、落下ダメージ(5ブロック以上)、voidダメージ、溺死、ブロック硬度に応じた破壊時間、ドロップ取得(手元)
- クリエイティブ: 飛行(Space上昇/Shift下降、ダブルSpaceでON/OFF)、即破壊、非ダメージ、無限アイテム
- 目線到達 6ブロック

## 8. レッドストーン(Java 1.13 仕様) — 最重要モジュール
### 8.1 電力モデル
- 弱電力: 水平4隣接ブロックに与える。強電力: 上(下方のブロックが上に与える)に与える
- 電源(出力15): レッドストーントーチ(無電源時)、レバーON、ボタン、圧力プレート(踏圧時)、オブザーバ(検出後2tick)、レドストーンブロック(弱+強)、ディスペンサ/ドロッパー(中身あり)、ハッパー(中身あり、後方のみ)
### 8.2 ダスト伝播(1.13準拠の固定点法)
- 各ダストの強度 0-15 を、全ダストについて反復計算(固定点まで、最大N回):
  - 水平隣ダスト N: `s(N)-1`
  - 水平隣電源ブロック N: `power(N)-1`
  - 下ブロックの強電力: `strongPower(below)`(例: レドストーンブロック上のダスト=15)
  - **ラインルール**: 水平直線上2つ先のダスト C に対して、C が既に強度15の場合のみフル強度(15)を減衰なしで与える。それ以外の場合は通常の隣接伝播(sN-1)のみ。これにより単調減衰(14,13,…)が保たれ、自己維持ラインは起きない(1.13準拠)。
- 変化があれば隣接ブロックの電力状態・ランプ点灯・コンポネント入力を再計算し、伝播再実行(ループ防止のため変更なしで収束するまで)
### 8.3 コンポーネント(20TPS, tick=50ms)
- **リピータ**: 背後から入力、1~4tick遅延で出力=入力強度(維持)。出力ON中はロック(切替不可)。右クリックで遅延1→4切替
- **コンペア**: compare= max(back, side1, side2)、subtract= max(back-side, 0)、出力=入力強度維持。右クリックでモード切替
- **ピストン**: 給電→約2tick後に伸展(最長12ブロック、ピストン含む連鎖。bedrock等は不可)、非給電→約2tick後に縮小。stickyは縮小時に前面ブロックを引きずる。伸展中に前面が変わった場合は縮小
- **オブザーバ**: 前面ブロックの状態変化を検出→2tick間出力15(弱+強)
- **トーチ**: 供給電力(隣4+下)を受けたら消灯
- **ランプ**: 6隣接の弱電力または下の強電力で点灯(meta切替)
- **ボタン**: 石=10tick/木=20tickで自動OFF
- **圧力プレート**: 上1マスにエンティティが存在なら15
- 非同期禁止: すべてゲームティック同期で処理
### 8.4 テスト必須シナリオ
- トーチ→ダスト15マス→強度10、16マス目で0(減衰)
- ラインルール: 強電源の横のダストが既に十分強い場合、2つ先へフル強度伝播
- リピータ: 遅延1tickで遅延信号伝播、信号維持(4tick点灯維持)
- コンペア: 減算モードで back-side、比較モードで max
- ピストン: 12ブロック推進、13ブロック目(非ピストン)で不可、sticky引きずり
- オブザーバ: ブロック置換で2tick出力

## 9. UI
- ホットバー(9枠、数字/ホイール、選択枠ハイライト)
- 心・ドラムスティックバー(サバイバルのみ、Canvas描画)

## 10. 品質基準・完了条件
1. `npm run dev` で起動し、16×16チャンクの地形が見える
2. サバイバル/クリエイティブで移動・採掘・設置・インベントリ動作
3. 8.4のレッドストーン全シナリオがテストで合格(ブラウザなしのユニットテスト)

5. スクリーンショットで地形・HUD・レッドストーン点灯を確認
6. gitにコンミット履歴が整備済み
7. 表示距離内の_CHUNKメッシュで30FPS以上(高PC基準)

## 11. フェーズ計画
- **Phase 1 (core)**: スキャフォールド+git、ブロック定義、チャンク/World、メッシャー、プレイヤー物理、基本HUD、簡易地形(平坦+ノイズ高さのみ)、Vitest導入。→ 起動してブロックの破壊/設置できる
- **Phase 2 (並列3モジュール)**:
  - A. terrain: 本番地形生成(バイオーム・樹木・鉱石・水)+テスト
  - B. modes: サバイバル/クリエイティブ完全実装+インベントリUI+ホットバー+F3+効果音
  - C. redstone: 伝播ネットワーク+全コンポーネント+テスト
- **Phase 3**: 統合・バグ修正・レビュー(Reviewロール)
- **Phase 4**: スクリーンショット検証・最終コミット
